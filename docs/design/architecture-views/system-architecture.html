Agent processes

TargetRust Coding Agent

Selected Rust executable with a ReAct action/observation runtime.

The Agent is a separate process with its own lifecycle, provider/runtime state, policy, durable sessions, and multi-Agent scheduling. Its Rust executable is selected, but the current Rust product scaffold is not yet production-composed; do not mistake its CLI stub or compile status for a connected model/tool loop. The target includes one real OpenAI-compatible streaming adapter configured by a nonsecret --provider-config file and native secret references, with deterministic local HTTP/SSE fixtures rather than remote calls during engineering tests. ReAct remains the default runtime pattern, with an optional revisable plan inside the loop.

TargetIDE operation dispatcher

Typed ACP requests flow through the Agent Client to real buffer and daemon service owners.

The selected path polls requests through vityod into the shared AgentClientRegistry dispatcher. The ACP methods are fs/read_text_file, fs/write_text_file, terminal/create, terminal/output, terminal/wait_for_exit, terminal/kill, and terminal/release. Flow Hero operations resolve only an active path-bound BufferFile; persistence uses the daemon workspace document read and atomic transaction contract, while terminal actions use vityod PTY. Pathless demonstration buffers stay unavailable. This gateway is a target until the operation port is composed with those owners and deterministic contract checks pass.
